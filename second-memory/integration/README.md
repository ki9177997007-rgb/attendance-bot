# Приём расшифровок без Omi

Первый прототип: подключённый Activepieces хранит текст; ChatGPT читает архив через уже доступные инструменты. Это не требует отдельного OpenAI API-ключа для чтения из чата. Автоматический запуск ChatGPT после поступления записи этим прототипом не обеспечен. Наличие моделей Activepieces не означает бесплатность их вызовов; они не включены.

Сценарий «Вторая память — приём расшифровки v1» создан как черновик. Проверка с искусственными данными прошла: валидация → запись строки → подтверждение. Сетевой вызов с телефона, авторизация реального HTTP-запроса и длительная работа ещё не проверены. Не публиковать до проверки лимитов сервиса и авторизации.

## Контракт v1

POST по настроенному HTTPS-адресу синхронного приёмника; Content-Type: application/json. Общий секрет передаётся только заголовком X-Memory-Token, хранится отдельно от исходников и защищается Android Keystore на телефоне. Не встраивать секрет в APK.

Поля JSON:

- segment_id: неизменный номер фрагмента, ASCII буквы/цифры/точка/дефис/подчёркивание, до 160 символов;
- session_id: номер сессии в том же алфавите, до 120 символов;
- recorded_at: целое время начала фрагмента в миллисекундах Unix;
- text: оригинальный непустой текст, до 24000 символов.

Ответ после записи: accepted=true, исходный segment_id, content_sha256. Контрольная сумма — SHA-256 от UTF-8 JSON-массива [segment_id,session_id,recorded_at,text]. На телефоне нельзя подтверждать отправку только по HTTP 200: проверять тело ответа, идентификатор и контрольную сумму. Подтверждение сохранения не равно завершённому анализу.

При потере ответа телефон повторяет передачу с теми же данными. Черновик приёмника пока допускает повторные строки; до включения нужна дедупликация для чтения и создания задач. Повторный id с другим содержимым — конфликт, а не перезапись. Не заявлять exactly-once по наличию одного поля id: простая операция найти→вставить не атомарна при параллельных запросах.

Тесты валидатора: node --test second-memory/integration/intake-validator.test.mjs из корня репозитория. Они не подтверждают сетевую авторизацию или работу Android.

Следующий этап: очередь исходящих на телефоне, защищённая настройка приёмника, сетевые проверки, дедупликация и обмен с YouGile. Ключи, адрес личного webhook и данные аккаунта в репозитории отсутствуют.
